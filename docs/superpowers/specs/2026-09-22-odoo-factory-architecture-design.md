# Odoo Factory ERP Framework & Agent Operating System — Design Specification

**Status:** APPROVED TARGET (Approach 1.1)  
**Date:** 2026-09-22  
**Target System:** Odoo 18.0 Community + PostgreSQL 16 + Docker  

---

## 1. Executive Summary & Goals

Transform the existing monolithic Odoo codebase into a modular, reusable **Factory ERP Framework** capable of adapting to any discrete or process manufacturing domain (apparel, furniture, metals, food, plastics, electronics).

### Key Architectural Tenets
1. **Strict Ownership Boundaries:** Vendor code (OCA/Core) is strictly separated from project-owned custom code.
2. **Flat Custom Addons Root:** Single `custom/` directory for all proprietary addons to ensure native Odoo discovery without recursive filesystem hacking.
3. **Declarative ERP Engine:** Business capabilities and install profiles defined declaratively in `.factory/`, backed by auto-generated catalog/dependency graphs.
4. **Decoupled Runtime Lifecycle:** Clean separation between continuous server runtime (`docker compose up`), idempotent environment bootstrap (`scripts/bootstrap.*`), and targeted test execution (`scripts/test.*`).
5. **Agent Operating Manual:** Self-contained `odoo-factory-engineer` skill enabling AI agents to implement business requirements across models, views, reports, and workflows with zero context loss.

### Filesystem Ownership Policy
* **`addons/**` (Vendor):** READ-ONLY. Direct edits strictly prohibited. Custom behavior MUST be achieved via inheritance in `custom/`. If an upstream bug fix is unavoidable, it must be documented with an architectural exception log.
* **`custom/**` (Proprietary):** Primary extension zone. All modules adhere to standard Odoo 18 naming and structure conventions.
* **`.factory/**` (Contracts):** Machine-readable single source of truth for agents and CI.
* **`skills/**` (Agent):** Behavioral guidance instructing agents on how to read `.factory/` and modify `custom/`.

## 3. Docker Runtime Decoupling

### Current Problem
`docker-compose.yml` runs `command: odoo ... -i odoo_factory_all,clothing_factory_demo`, causing re-installation attempts on every restart and hard-coupling runtime to legacy packages.

### Target Solution
1. **Clean Runtime (`docker-compose.yml`):**
   * Services: `web` (Odoo 18), `db` (PostgreSQL 16).
   * Web volumes:
     * `./addons:/mnt/extra-addons`
     * `./custom:/mnt/custom-addons`
     * `odoo-web-data:/var/lib/odoo`
   * Addons path: `/mnt/custom-addons,/mnt/extra-addons/manufacture,/mnt/extra-addons/ddmrp,/mnt/extra-addons/stock-logistics-warehouse,/mnt/extra-addons/stock-logistics-orderpoint,/mnt/extra-addons/server-backend,/mnt/extra-addons/server-tools,/mnt/extra-addons/stock-logistics-workflow,/mnt/extra-addons/web,/mnt/extra-addons/stock-logistics-availability,/mnt/extra-addons/queue,/usr/lib/python3/dist-packages/odoo/addons`
   * Command: `odoo --load=base,web,queue_job -d odoo` (NO `-i` flag).
2. **Bootstrap Script (`scripts/bootstrap.ps1` / `scripts/bootstrap.sh`):**
   * Accepts `--profile [core|operations|advanced|full]` and optional `--demo`.
   * Executes headless container command: `docker compose run --rm web odoo -d odoo -i <resolved_modules> --stop-after-init`.
3. **Test Script (`scripts/test.ps1` / `scripts/test.sh`):**
   * Runs tests in an isolated headless test database: `docker compose run --rm web odoo -d odoo_test --test-enable --stop-after-init -u <target_module>`.

## 4. Metadata Engine Specification (`.factory/`)

### 4.1 `project.yml`
```yaml
project:
  name: odoo_factory
  version: "18.0.1.0"
  description: "Generic Universal Factory ERP Framework"

odoo:
  version: "18.0"
  edition: community
  container_name: odoo_factory_system

database:
  engine: postgresql
  version: "16"
  default_db: odoo
  test_db: odoo_test

paths:
  vendor_addons: addons
  custom_addons: custom
  skills: skills/odoo-factory-engineer
  docs: docs
  metadata: .factory

policies:
  vendor_code_read_only: true
  allow_test_modules_in_production: false
  require_tests_for_customization: true
  require_docs_update: true
  prohibit_direct_sql_ddl: true
```

### 4.2 `module_policy.yml`
Curated policy classification for every module:
* `classifications`: `CORE`, `OPERATIONS`, `ADVANCED`, `INTEGRATION`, `UI`, `DEV`, `TEST`, `HARDWARE`, `LEGACY`
* `rules`:
  * All `test_*` modules marked `TEST` (excluded from production profiles).
  * VLM / Lift modules (`stock_vlm_*`, `stock_vertical_lift*`) marked `HARDWARE` (opt-in only).
  * Base infrastructure (`queue_job`, `server_tools`) marked `INFRASTRUCTURE`.

### 4.3 `capabilities.yml`
Maps business capabilities to technical Odoo addons:
* `quality`: `quality_control_oca`, `quality_control_stock_oca`, `quality_control_mrp_oca`
* `scrap_management`: `scrap_reason_code`, `mrp_workcenter_scrap_reason`
* `ddmrp`: `ddmrp`, `ddmrp_history`, `ddmrp_packaging`
* `background_jobs`: `queue_job`, `queue_job_cron`
* `advanced_bom`: `mrp_bom_hierarchy`, `mrp_bom_version`, `mrp_bom_tracking`

### 4.4 Generated Metadata
* `scripts/factory/scan_modules.py` parses AST / `__manifest__.py` across all folders and produces:
  * `.factory/generated/module_catalog.json` (keys: repository, path, version, depends, installable, application, ownership)
  * `.factory/generated/dependency_graph.json` (complete directed acyclic graph)

## 6. Generic Golden Demo & Scenario (GS-001 to GS-016)

The Universal Demo (`custom/factory_demo`) provides domain-neutral master data:
* **Raw Materials:** `RM-001` (Sheet/Plate), `RM-002` (Fastener), `RM-003` (Fluid/Chemical)
* **Components:** `COMP-001` (Sub-assembly A)
* **Packaging:** `PKG-001` (Universal Box)
* **Finished Goods:** `FG-001` (Standard Industrial Assembly)
* **Work Centers:** `WC-CUTTING`, `WC-WELDING`, `WC-ASSEMBLY`, `WC-QUALITY`, `WC-PACKING`

### Scenario Sequence (GS-001 .. GS-016):
1. **GS-001:** Product Master validation (routes, BOM, UOM)
2. **GS-002:** Procurement & RFQ / Purchase Order creation
3. **GS-003:** Incoming Quality inspection (Pass / Hold / Fail)
4. **GS-004:** Inventory stock movement & lot tracking
5. **GS-005:** Manufacturing Order demand generation & material reservation
6. **GS-006:** Work Order progress tracking across work centers
7. **GS-007:** Scrap generation & reason tracking
8. **GS-008:** Finished Goods quality gate
9. **GS-009:** Sales Order quotation & confirmation
10. **GS-010:** Delivery order picking, packing & validation
11. **GS-011:** Customer Invoicing & Account Move reconciliation
12. **GS-012:** Customer Return & triage (Restock, Rework, Scrap)
13. **GS-013:** Automated replenishment triggers (Min/Max reorder rules)
14. **GS-014:** Security permissions & role segregation
15. **GS-015:** Factory QWeb reports generation (MO card, Pick list, Invoice)
16. **GS-016:** Queue Job async execution verification


### Agent Operating Rules
1. **Never edit `addons/**` directly.** Always create or modify in `custom/**`.
2. **Consult `.factory/project.yml` and `.factory/generated/module_catalog.json`** prior to proposing or locating models.
3. **Resolve Capabilities First:** Translate user business requests (e.g., "Add quality check") to capability mappings before touching manifests.
4. **Verify XML IDs and Model Signatures:** Check existing definitions before adding fields to prevent Duplicate ID or Collision errors.
5. **Enforce Impact Analysis:** Modifying a component requires running the mapped GS test scenario before declaring completion.

## 8. Implementation Roadmap (Phases)

* **Phase 1: Discovery** (Completed)
* **Phase 2: Architecture Skeleton** (Create `custom/`, `.factory/`, `skills/`, `scripts/`, `docs/`)
* **Phase 3: Custom Code Relocation** (`clothing_factory_demo` -> `custom/factory_vertical_clothing`, `odoo_factory_all` -> `custom/factory_profile_legacy_all`)
* **Phase 4: Decouple Docker** (Update `docker-compose.yml`, mount `./custom`, isolate runtime)
* **Phase 5: Automated Module Scanner** (`scripts/factory/scan_modules.py`, output `.factory/generated/`)
* **Phase 6: Module Policy & Classification** (`.factory/module_policy.yml`)
* **Phase 7: Capabilities Definition** (`.factory/capabilities.yml`)
* **Phase 8: Install Profiles** (`custom/factory_profile_core`, `operations`, etc.)
* **Phase 9: Factory Core V1 Build** (Foundational models & configs)
* **Phase 10: Generic Golden Demo** (`custom/factory_demo`)
* **Phase 11: Golden Scenario Tests** (`scripts/test.ps1`, GS-001..GS-016)
* **Phase 12: Agent Skill Deployment** (`skills/odoo-factory-engineer/SKILL.md` + workflows + references)
* **Phase 13: Automation Validation & Final Freeze**
